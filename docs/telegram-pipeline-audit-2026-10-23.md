## Точечное исправление в этой ветке

- Отрицательная проверка оригинала получает паузу 15 минут. Старые `skipped_stale`
  тоже учитывают паузу от `updated_at`. Раньше они проверялись и записывались почти
  каждый двухминутный цикл, даже когда глобальный поиск не находил ничего нового.
- После паузы разрешена повторная проверка оригинала: временно неполные анонимные
  метаданные не превращаются в вечный запрет публикации.
- `original_check_reasons` и до пяти `original_check_examples` показывают пост,
  ссылку, конкретную причину отказа, статус оригинала и безопасный текст ошибки.
- `queue_reasons_by_language` и `ready_by_language` отделяют размер сохранённого
  outbox от записей, готовых к проверке/отправке для соответствующего языка.

## Проверки

Локально: `node --test tests/telegram-pipeline.test.mjs` — 14 тестов после расширения поиска.
Тесты извлекают настоящий runtime из YAML; `main()` не вызывается.
Проверены удаление кодов на всех этапах, старые открытые quiz/packet, причины отказа
оригинала, пауза и её окончание, независимость новых постов от `uncertain`, очередь
постов/эфиров, GitHub 500 до записи, потеря ответа после записи, остановка после
трёх неподтверждённых записей, сохранение `sent`/`uncertain` при конфликте.
YAML разобран; search и publisher используют один и тот же runtime anchor.

После применения в main проверить два последовательных плановых запуска:

1. Все четыре артефакта импортированы; worker `codes` отсутствует.
2. Старые четыре отказа показываются как `original_recheck_cooldown`; их оригиналы
   не вызывают повторные записи состояния до окончания 15 минут.
3. После паузы у каждого отказа появляется точная причина в `original_check_examples`.
   Для поста 380205898205153 проверить отдельно ошибку схемы ответа оригинала.
4. Для нового подтверждённо открытого поста: `ready_by_language`/результаты импорта →
   проверка оригинала → `sent_by_queue.posts` → запись `sent` с `message_id`.
5. Если `sent: 0`, по сумме причин должно быть видно, что все записи уже отправлены,
   ожидают повторной проверки, имеют неподтверждённую доставку или не проходят оригинал.
6. Три активных `uncertain` сверять с историей Telegram вручную перед решением о повторе.

Статус применения и проверок новых запусков указан в PR №3 и GitHub Actions.

Проверенный цикл 39937232714: 1322 уникальных записи глобальных источников,
440 замеченных авторов, новых авторов — 0. Теги на глубоких страницах возвращали
архив вплоть до 2024–2025 годов. Из 2983 сохранённых профилей за цикл проверялись 256.
Это показывает повторяемость охвата, но не доказывает отсутствие новых раздач во всём Square.

В этой ветке расширение:

- Сохраняются основные английские, русские, китайские и отдельные арабские источники.
- Два дополнительных запрашиваемых языка меняются каждые две минуты: es/pt-BR,
  tr/fr, vi/id. Полный набор обходится за три двухминутных окна при регулярных запусках.
- Добавлены рекомендации на базовых и выбранных дополнительных языках.
- Первые страницы глобальных лент и рекомендаций идут перед глубокими страницами тегов.
- Максимум профилей: 256 → 320; 128 активных авторов сохраняют квоту,
  исследование и подписки получают по 96 вместо 64. Временной бюджет и параллелизм прежние;
  фактическое число проверенных профилей видно в diagnostics.
- Внутри возрастной группы проверка оригиналов отдаёт приоритет явным признакам пакета,
  затем точным словам и свежести, затем сообщениям только с эмодзи.
- Добавлены местные названия пакетов: sobre rojo, pacote vermelho, kırmızı paket,
  enveloppe rouge, lì xì, angpao, 紅包. Это только повод прочитать оригинал;
  без подтверждённых метаданных пакет не публикуется.
- `feed_coverage_by_language` считает уникальные ID и ID вне основной английской выдачи.
  Запрошенный язык не гарантирует отдельную аудиторию: API может вернуть fallback/дубли.
- Ветка содержит отдельную проверку публичных источников без Telegram и записи истории.

Проверять после запуска: новые уникальные ID по дополнительным источникам, новые авторы,
готовые кандидаты и подтверждённые отправки по полным дневным часам. Рост объёма не
гарантируется заранее: раздачи должны существовать и пройти прежние проверки доступности.
